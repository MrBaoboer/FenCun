# 声音与文案

> 氛寸说话为什么是这个味儿。本文把散落在代码里的文案人格显性化成规范——所有例句均摘自仓库真实文案，注明出处；给氛寸写字之前，请先读完它。

---

## 一句定位

**氛寸的声音，是一位懂香水的朋友**：判断笃定、语气克制、永远给退路、绝不谄媚。

这不是形容词，是 `src/app/api/explain/route.ts` 里 SYSTEM 提示的铁律原文：「语气克制、温暖、不谄媚、不堆砌形容词。2~4 句话，像对朋友说话。」品牌句只有一句——**让每一瓶香，都用在它最好的那一刻**（README.md / docs/氛寸-产品方案.md）。朋友的意思是：他会直说「今天不太建议用这瓶」，但话锋一转告诉你硬要用该怎么把影响降到最低；他记得你上次说「太冲了」，下次默认帮你少喷半下；你不听他的，他也不追问，围着你的选择重新出主意。

## 绝不说 / 永远这样说

| 绝不说 | 永远这样说 |
|---|---|
| 社群腔与客服腔（「宝子」「亲~」「家人们」），感叹号堆叠 | 像对朋友说话，2~4 句成段（explain SYSTEM 铁律 3） |
| emoji——产品文案 emoji 数量为零（`src/` 全目录 grep 核实：零命中） | 用词本身带温度：「明天见」「一句就够」 |
| 无法验证的精确数字（「留香 6.2 小时」「扩散半径 1.5 米」）——这条是**代码级**的：LLM 输出里出现任何我们没给过的数字，整段丢弃退模板（route.ts 数字白名单防线） | 体感替代数字：留香说「大半个白天」，距离说「一臂之内」，喷量说「2–3 下」（format.ts / usage.ts） |
| 否定用户的选择——换瓶后卡片标题变「你选了 · Your Pick」，围绕新选择重算建议，不说「其实我更推荐」 | 顺势服务：你换哪瓶，就讲哪瓶在今天的真实表现 |
| 为讨好用户把该劝退的圆成可用——avoid 裁决的回复若不含否定语义，**代码强制回退**确定性模板（route.ts 防线①） | 先诚实后补救：「说实话，今天不太建议用……你要是今天就想用它，就……把存在感压到最低」（route.ts 模板原文） |
| 命令式恐吓（「千万别」「你必须」） | 后果描述 + 出路：「空间偏封闭、人也多，这瓶气场较大——建议只喷 1 下，或换一瓶更贴肤的。」（usage.ts） |
| 出错时甩锅或吓人 | 先安数据的心：「你的香柜与全部反馈都存在本机浏览器里，没有丢。」（error.tsx） |

## 体感语言对照表

档位与话术在 `src/lib/format.ts` 一一对应，写文案不得另造叫法。

**留香四段**（社区 longevity 均值 → 话术，永不给小时数）：

| 档 | 完整话术（`durationHint`） | 速览（`durationShort`） |
|---|---|---|
| < 2 | 较快淡去，约半天，午后可补喷 | 约半天 |
| 2–3 | 大半个白天，傍晚有场合可补 | 大半个白天 |
| 3–4 | 基本撑一整个白天 | 一整个白天 |
| ≥ 4 | 可能延续到夜晚，少喷即可 | 可能到夜晚 |
| 无数据 | 留香表现因人而异 | 因人而异 |

手动录入的香没有社区数据，留香话术自动落「因人而异」——**不假装知道**（ManualAdd.tsx 注释即规范）。

**社交距离四档**（sillage tier → 三套一致口径）：

| 档 | 完整（`DISTANCE_LABEL`） | 速览简写（`SILLAGE_WORD`） | 规格副标签（`DISTANCE_SUB`） |
|---|---|---|---|
| 1 | 贴身可闻 | 贴肤 | 密闭也安全 |
| 2 | 一臂之内 | 一臂 | 日常安全 |
| 3 | 一桌之间 | 一桌 | 注意场合 |
| 4 | 整间屋都是它 | 满室 | 密闭慎用 |

**喷量**：一律「N 下」句式——`2 下` 或区间 `1–2 下`（usage.ts `spraysLabel`），不用「喷次」「泵」，更不用毫升。

## 真实文案范例集

以下每条都是仓库里正在线上跑的原文。

1. **「今天，刚好吗」** —— FeedbackBar.tsx 反馈栏标题。四个字问完一整个反馈闭环，「刚好」还是产品名里那个「分寸」的日常说法。
2. **「记下了——不过今天这天气本来就吃留香，这笔算天气的，不扣它的分。」** —— FeedbackBar.tsx 环境归因确认语。把一条算法逻辑（闷热天的「淡了」不计入瓶子的喷量修正）说成了替香水说的一句公道话。
3. **「今天这瓶已经记过了。明天见。」** —— FeedbackBar.tsx 当日去重态。不解释机制，只留一个轻的告别，克制到只剩必要信息。
4. **「报上香名，请它入柜 →」** —— EmptyShelf.tsx 空柜按钮。「请它入柜」把添加动作写出了仪式感，香水是被礼待的客人，不是被录入的数据。
5. **「可能是网络波动。你香柜里的 N 瓶香水都还在，没有丢——点下面重试就能恢复今日推荐。」** —— page.tsx 目录加载失败态（N 为实时瓶数）。故障文案的第一职责是安心：先报平安，再给动作。
6. **「这天没有记录。无香的日子，也是分寸。」** —— journal/page.tsx 香历空白日。一句话立住「留白不谴责」的产品立场——没有断签，没有补打卡。
7. **「没搜到。试试英文名或品牌名——有些香水的中文昵称和官方名差得很远。」** —— SearchAdd.tsx 搜索无结果。不说「无结果」，而是给出一个真实的领域知识当台阶。
8. **「这句没读懂。换个说法试试，或直接点上面的场合。」** —— SceneInput.tsx 场景解析失败。承认没读懂是自己的事，且永远附一条退路。
9. **「出了点问题，这不是你的错」** —— error.tsx 错误边界标题。技术故障里最先处理的是用户的自责。
10. **「今天，刚刚好」** —— greeting.ts 天气问候兜底句。拿不到任何天气特征时的最后一句话，也是品牌态度本身。

## 反馈提问的克制原则

反馈是推荐引擎的养料，但氛寸问得极省（均为 FeedbackBar.tsx 代码级行为）：

- **一次一题**：只有「今天，刚好吗」一问，四个选项（淡了点 / 刚好 / 太冲了 / 不合场合），点一下即完成，没有第二屏。
- **每瓶每天一次**：按当日去重，答过即收起，刷新页面也不再问——「今天这瓶已经记过了。明天见。」
- **答完只说一句确认**：每个选项对应一句固定回执（如「记下了，下次默认帮你少喷半下。」），说完即止，不追问、不弹评分、不求好评。
- **归因诚实**：闷热天反馈「淡了点」会被记为环境因素，确认语明说「这笔算天气的，不扣它的分」——不让用户的反馈被错误消化，也不让香水背天气的锅。

---

写新文案时的自检三问：这句话有没有一个可执行的判断？数字是不是档位或我们真给过的事实？用户不听的时候，这句话还给没给他留台阶？三个都过，才像氛寸说的。
