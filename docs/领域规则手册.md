# 氛寸 · 领域规则手册

这本手册是氛寸推荐引擎的领域知识层，也是它的设计资产库。前者回答「引擎为什么这样打分、这样给喷量」——每条规则都指认到源码里的文件与函数，可以逐一对着代码核对；后者是尚未编码的用香领域规则储备，供后续迭代与讨论。两者在这里严格分开标注，不混写。

> **约定**
>
> - **实现状态**：✅ 已进引擎（附「文件:函数」指认，代码里一定有）；🌱 设计资产·未实现（代码里一定没有，明说它是储备）。诚实本身就是这本手册的卖点——这个项目吃过文档言过其实的亏，所以宁可让 🌱 显得多，也不让任何一个 ✅ 掺水。
> - **置信度**：【共识】物理化学原理或行业公认 /【经验】主流从业者经验判断 /【假设】合理推断，需上线后用反馈数据验证。
> - **数值口径**：领域量一律档位与区间，禁裸小数——用户永远看不到「留香 6.2 小时」。手册里出现的小数只有一种合法来源：引擎中的代码常数（如 ×0.82 的天气修正），每一个都能在指认处核对。
> - **术语口径**：全部以仓库实现为准，本手册没有第二套叫法。速查见下表。

## 1. 环境 × 香水表现的物理规则

### 1.1 四条底层原理【共识】

所有环境规则由这四条推出，✅ 以 §1.2、§1.3 的具体规则落地：

1. 温度越高，香料分子蒸气压越大 → 挥发越快 → 短期扩散更强、总留香更短；
2. 湿空气传导气味的体感强度高于干空气 → 高湿 = 同样的量闻起来更浓；
3. 皮肤越干（低湿、冬季），香水「挂不住」；油脂能延缓挥发；
4. 密闭空间气味累积，开阔通风空间气味稀释。

### 1.2 体感四态判定 ✅ `season.ts:feelFromWeather`

温湿度不各自为政，先合成一个体感，再让体感驱动打分与喷量：

| 体感 | 判定条件 | 说明 |
|---|---|---|
| 闷热潮湿 | ≥28℃ 且湿度 ≥65%；**或 20–27℃ 且湿度 ≥85%** | 第二条是回南天 / 梅雨规则：对中国市场，「28℃ 以下一律温和」不是体感真相——气味在湿空气里散不掉，甜香白花被放大，按闷湿处理【经验】 |
| 干热 | ≥28℃ 且湿度 <65% | — |
| 寒凉 | ≤10℃ | — |
| 温和 | 其余 | 11–27℃ 的大多数日子 |

配套的季节判定也不只看月份：≥28℃ 一律按夏、≤6℃ 一律按冬，极端温度盖过日历直觉（✅ `season.ts:seasonFromDateTemp`，详见 §6.2）。

### 1.3 体感 × 香调的修正 ✅ `scoring.ts:weatherMultiplier`

天气对总分是乘性修正 W，钳位在 [0.7, 1.3]。先定义三个家族：

- **厚重家族**：sweet、vanilla、amber、resinous、animalic、oud、tobacco、honey、caramel；
- **清爽家族**：citrus、aquatic、marine、green、aromatic、fresh、ozonic；
- **取暖判定**：amber / warm spicy / vanilla / resinous / leather / sandalwood 任一强度 ≥45；或 woody ≥45 且 amber / resinous / warm spicy 最强者 ≥40。裸 woody 不算暖——「木质」是最宽的家族，干冷的香根草、干雪松并非取暖型香，必须组合判定。

| 体感 | 命中 | 修正 |
|---|---|---|
| 闷热潮湿 | 厚重家族任一 ≥50 | ×0.82（闷湿压重香） |
| 闷热潮湿 | 清爽家族任一 ≥45 | ×1.16 |
| 干热 | sweet / amber / resinous 最强 ≥55 | ×0.92 |
| 干热 | citrus / aromatic / woody 任一 ≥45 | ×1.1 |
| 寒凉 | aquatic / marine / ozonic / citrus 任一 ≥50 且非取暖型 | ×0.9（纯柑橘古龙在严寒里最薄、飘、留不住；取暖守卫防止误伤东方柑橘）|
| 寒凉 | 取暖型 | ×1.15 |
| 温和且 ≥23℃ | 清爽 ≥45 → ×1.05；厚重 ≥55 → ×0.96 | 温和区间不再恒等于 1，急性温度在温带也有区分度 |
| 温和且 ≤15℃ | 取暖型 → ×1.05；纯水生 ≥55 且非取暖 → ×0.96 | 同上 |

修正方向全部来自 §1.1 的原理【共识】，具体系数是工程取值【经验】，验证方式见附表。

### 1.4 环境规则储备 🌱

以下规则在底层原理上站得住，但当前引擎没有实现，保留为储备：

- **极寒锁香**（<5℃）【共识】：柑橘、水生、绿叶前调发闷、几乎没有开场；建议改喷衣物内侧 / 围巾。附带一条翻车提示：室外闻不到 ≠ 没喷够，进暖气房温差会让香气集中释放，忍住别补喷。
- **干燥润肤**（低湿 / 北方冬季 / 空调房）【共识】：皮肤干「挂不住」香，正确动作不是多喷，是先涂无香身体乳——油脂延缓挥发，比多喷有效。
- **大风改衣物**【经验】：大风天皮肤喷洒基本「白喷」，建议改喷衣物内侧锁香。风速已随情境采集（`types.ts:Context.windSpeed`），但尚未参与任何打分与喷量计算——这是最接近「一行就能进引擎」的储备。
- **户外放风日**【经验】：全天开阔通风，等效扩散低一档，强扩散香的「放风日」，喷量可放宽一下。

## 2. 留香与扩散：社区投票 → 档位

### 2.1 为什么不用浓度标签 ✅（以数据契约落地）

两条行业常识【共识】：

- **浓度决定不了留香，香调结构才是大头**：柑橘古龙做成 EDP 依然短命，乌木做成 EDT 依然顽固；
- **浓度与扩散不是单调关系**：Extrait 往往比 EDP 更贴肤绵长，「浓度越高越冲」是外行规则。

所以氛寸的数据层根本没有浓度字段（`types.ts:Perfume`）——留香与扩散一律来自社区投票（longevity 1–5、sillage 1–4），浓度标签不参与任何计算。这不是偷懒，是立场。

### 2.2 扩散四档 ✅ `scripts/derive.mjs:sillageTier` + `format.ts`

| sillage 均值 | 档 | 档名 | 速览 | 副标签 | 一句话（`DISTANCE_HINT`） |
|---|---|---|---|---|---|
| <1.75 | 1 | 贴身可闻 | 贴肤 | 密闭也安全 | 适合电梯、会议、就医等密闭场合 |
| 1.75–2.5 | 2 | 一臂之内 | 一臂 | 日常安全 | 正常社交距离可感，安全日常 |
| 2.5–3.25 | 3 | 一桌之间 | 一桌 | 注意场合 | 同桌或小房间能闻到，注意场合 |
| ≥3.25 | 4 | 整间屋都是它 | 满室 | 密闭慎用 | 户外、夜场加分，密闭空间慎用 |

无投票数据落第 2 档（取中庸，不假装知道更多）。推荐卡、香柜卡、换瓶弹层对同一瓶的叫法从这一套出，不另造词。

### 2.3 留香四段 ✅ `format.ts:durationHint` / `durationShort`

| longevity 均值 | 完整话术 | 速览 |
|---|---|---|
| <2 | 较快淡去，约半天，午后可补喷 | 约半天 |
| 2–3 | 大半个白天，傍晚有场合可补 | 大半个白天 |
| 3–4 | 基本撑一整个白天 | 一整个白天 |
| ≥4 | 可能延续到夜晚，少喷即可 | 可能到夜晚 |
| 无数据 | 留香表现因人而异 | 因人而异 |

永不给小时数。一条已实现的联动：场景解析出的在场时长 ≥6 小时档、且这瓶撑不到一整个白天（longevity <3）→ 话术追加「在外时间不短，带上分装中途补 1 下更稳」（✅ `usage.ts:computeUsage`）。

### 2.4 低票与手动记录：不确定性外显 ✅

- 扩展集低票记录（国货白名单等）带 `lowVotes` 标记，解释文案明说「这瓶的社区数据还少，判断偏保守，你的反馈会让它更准」（✅ `usage.ts:buildReasons`）；
- 手动建卡（`custom`）没有社区数据，按所选香调的典型情况估计，留香话术自动落「因人而异」——**不假装知道**（✅ `types.ts` + `format.ts`）。

### 2.5 浓度基线（设计资产）🌱【共识】

浓度不进引擎（§2.1），但作为领域参考保留——若未来允许用户手动标注浓度，可作为低票记录的兜底先验。典型区间（行业通识，永不直接输出给用户）：

| 类型 | 香精浓度 | 典型留香 | 典型扩散（按仓库四档） |
|---|---|---|---|
| EDC 古龙水 | 约 2–6% | 1–2 小时 | 贴肤～一臂 |
| EDT 淡香水 | 约 5–15% | 3–5 小时 | 一臂 |
| EDP 淡香精 | 约 15–20% | 5–8 小时 | 一臂～一桌 |
| Parfum / Extrait | 约 20–30% 以上 | 8 小时以上 | **贴肤～一臂（投射反而低）** |
| 香水油 / Attar | 无酒精 | 贴肤 6 小时以上 | 贴肤，几乎无投射 |

## 3. 喷量与位置

### 3.1 喷量基础档 ✅ `usage.ts:computeUsage`

扩散越强，喷越少：

| sillage 均值 | 基础档 |
|---|---|
| ≥3.2 | 1–2 下 |
| 2.4–3.2 | 2–3 下 |
| <2.4 | 3–4 下 |

缺数据按 2.5 处理，落 2–3 下。注意这组切点（2.4 / 3.2）与扩散四档的命名切点（2.5 / 3.25）是两套独立常数，方向一致：扩散更强 → 更少。

### 3.2 修正叠加 ✅ `usage.ts:computeUsage`

修正按档位递推（在区间上加减 1），不做加权求和：

| 修正 | 条件 | 动作 |
|---|---|---|
| 密闭 / 人挤 | 场合密度为 dense（通勤）或 closed（上班、正式场合），见 §4.1 | 上下限各 −1 |
| 寒凉 × 清淡 | 体感寒凉且 sillage <2.4 | 上限 +1 |
| 闷湿 × 强扩散 | 体感闷热潮湿且 sillage ≥3.2 | 上限 −1（湿热天强扩散香更容易发闷、放大存在感）|
| 餐桌 | meal 开关命中（§5.2） | 上限 −1 |
| 「用力过猛」组合 | 见 §4.5 | 直接压到 1 下 |
| 想贴身 | 场景解析 intimacy = close | 上限 −1 |
| 想被注意到 | intimacy = broadcast | 上限 +1 |
| 明说别太冲 | avoid 含 too_strong | 上下限各 −1 |
| 个人校准·嫌冲 | perceivedStrength ≥0.4 | 上限 −1；≥0.7 时下限再 −1 |
| 个人校准·嫌淡 | perceivedStrength ≤−0.4 | 上限 +1 |

**不变式收口**：任何修正路径之后强制 1 ≤ lo ≤ hi ≤ 5——绝不出现「2–1 下」这种反向区间。输出话术固定为「N 下」或「lo–hi 下」。

### 3.3 成功配置复用 ✅ `usage.ts` + `recommend.ts:aggregateBias`

同温度档 × 同场合，你曾对这瓶反馈过「刚好」→ 跳过上面全部通用修正，直接用那次的量（取当时建议区间的中值），并显式说明：「上次同样天气、同样场合你说『刚好』——就按那次的量来。」成功配置同键只留最新一条，每瓶至多 5 条。校准必须被感知，见 §7.6。

### 3.4 位置策略（已实现部分）✅ `usage.ts:computeUsage`

| 情境 | 位置 |
|---|---|
| 想贴身（close） | 手腕、颈侧贴身 |
| 密闭场合（通勤 / 上班 / 正式） | 手腕、衣物内侧 |
| 约会 | 颈侧、手腕、发梢少量 |
| 聚会 | 颈侧、胸口 |
| 其余 | 手腕、颈侧 |

两条覆盖规则：

- **闷热潮湿改写**：手腕 → 衣物内侧；颈侧 → 耳后 / 衣领内侧；胸口 → 衣物内侧；发梢剔除。颈侧、胸口是脉搏 + 出汗区，高温加速挥发、易发闷酸，一并降到低出汗部位【共识】。
- **「用力过猛」组合**：位置整体放低到腰侧、衣物下摆内侧——热空气自下而上，浓香从低位缓释才体面【经验】。

**有效社交距离** ✅：推荐卡上展示的距离档取「喷后有效档」而非原始扩散档——已生效的减档（密闭、贴身、明说嫌冲、个人校准嫌冲）每项降 1 档、封顶降 2 档，避免同屏出现「喷 1 下」却仍标「整间屋都是它」的自相矛盾（`usage.ts` 中 effTier 的计算）。

### 3.5 完整位置策略表 🌱

引擎目前只用到上面的子集。完整的位置知识如下，是本手册最成体系的储备之一：

通用前提【共识】：喷距 15–20cm，成雾面覆盖而非湿点；喷后**不要摩擦手腕**——揉搓加速前调挥发、压扁层次。

| 位置 | 适用条件 | 扩散特点 | 禁忌 / 风险 |
|---|---|---|---|
| 手腕 | 万能默认位 | 脉搏点体温助扩散，中等 | 频繁洗手的人（医护、餐饮、带娃）别选【经验】 |
| 颈侧 | 想要社交距离存在感 | 体温最高点之一，扩散最强 | 高温出汗日避免；含柑橘精油的香在暴晒日有光敏风险（香柠檬内酯致色素沉着）【共识】；一桌 / 满室档喷颈侧 = 礼仪风险放大器 |
| 耳后 | 约会、近距离交谈 | 同颈侧但更收敛，「凑近才有」 | 同颈侧的光敏提示 |
| 锁骨 / 胸口 | 正式场合的安全位；自我愉悦 | 香随体温上升，自己全天闻得到 | V 领时略外放 |
| 衣物（内衬 / 围巾 / 衣角） | 冬季主力位；大风天；最大化留香 | 纤维锁香最久，但无体温发展，香偏「平」【共识】 | 深琥珀色香液在浅色真丝 / 羊毛上留渍【共识】→ 一律建议内衬、距离 20cm 以上；名贵面料直接提示别喷 |
| 发梢 | 「走动生香」场合（约会 / 聚会） | 头发留香久，移动时释放 | 酒精伤发 → 20cm 以上，或喷梳子梳过【共识】；油性发质慎用 |
| 腰际 / 后腰 | **一桌 / 满室档的默认降压位**；正式、密闭场景首选 | 热空气上升，香气自下而上缓释，浓香变体面【经验】 | 冬季厚外套下效果打折 |
| 膝后 / 脚踝 | 裙装、夏季；满室档的「唯一安全位」 | 最低调的缓释 | 冬季长裤长靴下基本无意义 |

可直接编码的位置决策规则（储备）：贴肤 / 一臂档 → 正常双位；一桌档 → 锁骨以下；满室档 → 仅腰际 / 脚踝 / 衣物内衬，任何情况不上颈；高敏感场景无视扩散档、仅低位单点；>28℃ 剔除颈侧耳后（引擎的闷湿改写已覆盖大半，干热日的剔除仍是储备）；<5℃ 追加围巾 / 外套内衬为第一推荐位。另：喷空中走过（spray-and-walk）覆盖均匀但浪费且留香最短，只对 Extrait、乌木类作可选项【经验】。

### 3.6 浓度 × 扩散喷量矩阵 🌱【经验】

与 §2.5 同命运：浓度进不了引擎，矩阵作为储备（若未来支持手动标注浓度）。环境标准态（温和体感、通风室内）下的基线：

|---|---|---|---|---|---|
| 贴肤 | 5–6 | 4–5 | 3–4 | 2–3 | 2–3 处点涂 |
| 一臂 | 4–5 | 3–4 | 2–3 | 1–2 | 1–2 处点涂 |
| 一桌 | 3–4 | 2–3 | 1–2 | 1 | 1 处点涂 |
| 满室 | — | 2 | 1 | 1 | 不建议 |

## 4. 场合 × 香调

### 4.1 八场合与空间密度 ✅ `types.ts:Occasion` + `usage.ts:DENSITY`

| formal | 正式场合 | closed（密闭） |
| date | 约会 | normal |
| social | 聚会 | normal |
| casual | 休闲 | normal |

密度进两处：喷量修正（§3.2）与密闭三道闸（§5.1）。

### 4.2 场合从哪来：场景理解 ✅ `src/app/api/parse-intent/route.ts`

用户可以点场合，也可以说一句话（「去前任婚礼」「第一次见投资人」）。一句话走 DeepSeek 解析 + zod 校验，产出结构化补丁：场合、正式度（0–1）、亲密距离（close / neutral / broadcast）、规避项（别太甜 / 别太冲 / 别太端着 / 别腻 / 别太随意）、关系张力、餐桌开关、受控的一句话社交风险、≤12 字的人话摘要。三条设计约束：

- **在场时长只许 2 / 4 / 6 / 9 档位值**——LLM 能输出任意数字，就会输出「7.5」这种没有信息量的伪精确，档位是代码级红线；
- **解析失败降级关键词启发式**，永远给出可用结构——婚礼、面试这类词在启发式里落到正式场合并自动挂上「别太冲」；
- **LLM 的场景常识只能走受控字段**（riskNote，≤40 字），不允许自由发挥进正文（§8.4）。

规避项的兑现在打分侧（✅ `scoring.ts:avoidPenalty`）：别太甜 / 别腻 → 甜系主调 ≥50 的一律 ×0.68；别太冲 → 满室档 ×0.6、一桌档 ×0.8；别太端着 → 带「正式商务」风格标签的 ×0.8；别太随意 → 「日常百搭 / 清新通勤」×0.85。

### 4.3 场合适配的方向表 ✅ `scoring.ts:occasionFit`

引擎不用「族群 × 场景」的巨型矩阵，用六个香调组 + 每场合一组加减方向，基准 0.5：

| 组 | 成员 accords |
|---|---|
| 清爽 | citrus, aquatic, marine, ozonic, green, fresh, watery |
| 甜感 | sweet, vanilla, caramel, honey, chocolate, coffee, gourmand |
| 琥珀木质 | amber, woody, oud, sandalwood, cedar, resinous, balsamic |
| 花香 | floral, white floral, yellow floral, rose, jasmine, tuberose, violet, iris |
| 泥土暗调 | earthy, leather, tobacco, smoky, animalic, patchouli |
| 辛香 | warm spicy, spicy, fresh spicy, cinnamon, soft spicy |

每组取成员中的最强 accord 强度（0–100 归一后）参与：

| 场合 | 加分 | 减分 |
|---|---|---|
| 约会 / 聚会 | 甜或花取大 +0.4；温和琥珀木质 +0.12（强度 60 以上斜坡淡出——连续函数，不设悬崖，60 / 61 之间不许出现总分跳变） | 泥土暗调与半权辛香（×0.5 折算）取大 −0.3；纯清冽（清爽 >70 且不甜不花）−0.15，安全但不够暧昧；约会且满室档 −0.15 |
| 正式 / 上班 / 通勤 | 干净木质（×0.75 折算）/ 清爽 / 辛香（×0.6 折算）取大 +0.3 | 甜 −0.42；花 −0.22；泥土暗调 −0.18；满室档 −0.2 |
| 运动 | 清爽 +0.42 | 甜 / 琥珀木质 / 泥土暗调取大 −0.45；一桌档以上 −0.1 |
| 居家 / 休闲 | 柔和皆可：甜、木、清爽、花各自打折后取大 +0.18 | 满室档 −0.15 |

**软下限**：结果低于 0.05 时不硬夹到常数，单调压缩进 (0, 0.05]——同质香柜多瓶一起撞底板会让场合项（0.43，最高权重）在该场景退化为同分、区分力归零，压缩保住候选间的相对次序。方向【经验】，系数【假设】，验证方式见附表。

### 4.4 香调组的一句话性格（文案素材库）🌱【经验】

不在代码里，供解释提示词与文案迭代取用：

- **清爽**：几乎零冒犯风险的社交货币，短板是夜场撑不住、消失快。
- **甜感**：亲密距离的大杀器、密闭空间的头号翻车源——饭味、腻感、「闻着像甜品店」。
- **琥珀木质**：中性、稳、显贵，几乎全场景可用的骨架；重琥珀在夏日白天是雷区。
- **花香**：浓郁华丽自带音量，密闭工位容易「抢戏」；婚宴与稳定期约会是主场。
- **泥土暗调**：存在感天花板，密闭日间场景一律高危；夜场与冬夜独处是正确打开方式。
- **辛香**：温暖有气场但音量大，低温夜晚最佳，白天办公室易显「冲」。

### 4.5 「用力过猛」组合 ✅ `usage.ts:overdressedCombo`

国内语境下最容易被负面评价的搭配，三个条件同时命中：

> （sweet 或 vanilla ≥50，或 white floral ≥50）×（扩散 ≥ 一桌档）×（通勤 / 上班 / 正式场合）

触发后三连：喷量直接压到 1 下、位置放低到腰侧 / 衣物下摆内侧、附风险文案——「甜和扩散都偏高，这类场合容易显得用力过猛——压到 1 下、放低位置会体面很多。」这条规则针对的是「柜姐感」联想【经验】：办公室里的浓甜白花，在国内的解读往往不是「讲究」而是「过了」。

### 4.6 特殊场景硬规则 🌱

八场合覆盖日常，但有几类场景值得专项硬规则，当前只由场景理解的通用通道部分承接：

- **医院探访**【共识】：病房嗅觉敏感人群 + 化疗患者气味不耐是明确共识，正确输出是「建议今天不喷；实在想喷，柑橘 / 水生类衣角一下」。当前八场合没有「就医」一档，只能靠一句话场景落到正式 / 休闲——这是最该补的储备。
- **婚礼出席**【经验】：「别抢新人风头，控制在一臂档以内」。parse-intent 的示例已经写了「婚礼焦点是新人，不宜喧宾夺主」的 riskNote（✅ 半实现），完整的专项压档仍是储备。
- **运动**【经验】：一律建议「运动后再喷」；坚持要喷 → 仅清爽类 1 下衣物。当前运动场合只做了反甜反重的打分（§4.3）。
- **见长辈 / 陪领导应酬**【经验】：按正式场合再收半档；酒桌上香水混白酒气味极差。

## 5. 气味礼仪与中国语境

### 5.1 密闭空间三道闸 ✅

同一个事实（强扩散 × 密闭）在引擎里过三道互相独立的闸，各管各的：

1. **喷量闸**：dense / closed 场合上下限各 −1（`usage.ts:computeUsage`）；
2. **风险闸**：满室档 × 密闭 → 风险文案「空间偏封闭、人也多，这瓶气场较大——建议只喷 1 下，或换一瓶更贴肤的。」（`usage.ts:computeRisks`）；
3. **裁决闸**：满室档 × 通勤 / 上班 / 正式 → 直接判 avoid，「今天不建议」（`recommend.ts:computeVerdict`）。

风险文案的句式是刻意的：后果描述 + 出路，不用「千万别」。

### 5.2 餐桌规则 ✅ `types.ts:Context.meal` + `usage.ts`

气味干扰味觉是餐饮共识，高端餐饮甚至明示谢绝浓香【共识】。meal 开关由场景理解给出（婚宴 / 日料 / 火锅 / 酒局都算），命中后：

- 喷量上限 −1（`computeUsage`）；
- 这瓶偏甜重（sweet / amber / vanilla 最强 ≥55）或扩散 ≥ 一桌档 → 风险文案「这顿饭是场合的一部分——它的存在感会和食物气味打架，喷得比平时更收着些。」（`computeRisks`）

### 5.3 中国语境的本土化差异【经验】

1. **整体容忍度低一档** ✅（弥散在参数取向里）：国内公共场合对明显香水味的默认反应偏负面（「好大味儿」是负面评价）。这条不对应某一行代码，而是解释了一批参数为什么取成这样——正式 / 上班 / 通勤对甜与花的重罚（−0.42 / −0.22）、满室档在密闭场合直接判 avoid。
2. **「柜姐感」联想** ✅：即 §4.5 的「用力过猛」组合，专项处理。
3. **回南天 / 梅雨** ✅：20–27℃ 但湿度 ≥85% 并入闷湿体感（§1.2），这是照抄欧美温标做不出来的判断。
4. **「若有若无的好闻」是国内最高频正面评价** → 产品默认审美是宁淡勿浓 ✅（体现于打分取向与 avoid 裁决）。底稿曾提议的「同分时选扩散更低的一瓶」tie-break 🌱 未实现——当前同分簇按日稳定轮换（§7.5），扩散档不参与破平。
5. **长辈 / 领导同席降半档、夏季地铁专项提示** 🌱：启发式已把「地铁」归入通勤（✅ 部分承接），专项规则是储备。

### 5.4 电梯与长途交通细则 🌱

- **电梯规则**【共识】：喷后 1 小时是投射峰值期——出门即乘早高峰电梯 × 扩散 ≥ 一桌档，是典型高风险组合。规避优先级：换更贴肤的香 > 减到 1 下 > 位置降到腰以下。
- **长途高铁 / 飞机**【经验】：邻座不可选择 + 密闭 4 小时以上 → 扩散 ≥ 一桌档一律高危；建议登车前 2 小时以上喷（错过峰值）或改喷衣物内侧。

这两条都依赖「喷了多久」的时序维度——当前引擎完全没有时间轴概念，是礼仪模块最值得补的一块。

## 6. 季节与时段投票的使用

### 6.1 平滑与相对主场归一 ✅

- **拉普拉斯平滑**：季节占比在数据构建期做平滑（ALPHA = 5），防低票噪声（`scripts/derive.mjs:seasonPct`）。
- **相对主场归一**：季节适配分 = 当前季占比 ÷ 该瓶最高季占比，主场得 1（`scoring.ts:seasonFit`）。不用「占比 >0.35 算夏香」式的绝对阈值——投票行为有系统性偏置，四季分布整体偏平的瓶子会被绝对阈值一刀切没。时段适配同构（`daypartFit`）：偏夜香在夜里得 1，避免原始占比方差太小、名义权重被稀释成没有影响力。

### 6.2 温度盖过月份 ✅ `season.ts:seasonFromDateTemp`

月份定基准季节，但 ≥28℃ 一律按夏、≤6℃ 一律按冬。理由是本土化的关键判断：Fragrantica 投票者以欧美温带用户为主，他们的「夏天」不是广州的夏天——本地实时气温比日历更接近体感真相。急性天气另有乘性修正兜底（§1.3），两层各司其职。

### 6.3 反季的两道门槛 ✅

主场季 ≠ 当前季时，按占比的**相对差**分两级：

- 差 ≥0.12 → 风险提示「大家更多在 X 季用它，今天用会有点反季。」（`usage.ts:computeRisks`）
- 差 ≥0.22 → 直接进 avoid 裁决（`recommend.ts:computeVerdict`）

用相对差而非绝对阈值，理由同 §6.1。

### 6.4 权重结构 ✅ `scoring.ts:score`

> 总分 = (0.38 × 季节 + 0.19 × 时段 + 0.43 × 场合) × 天气 W × 质量先验 Q × 个人偏好乘子 × 场合差评乘子 × 场景规避乘子

- **场合权重高于季节**：「今天去哪儿」比「现在什么季」更该决定喷哪瓶——急性温度已由 W 兜底，让场景赢下真正的平局。
- **质量先验 Q**：社区评分做贝叶斯收缩（C = 30，靶心 M = 4.0）后压进 [0.96, 1.04]——同一个香柜里「今天喷哪瓶」该由情境决定，社区评分只当轻微 tiebreak，不允许某瓶高分香跨场景通吃；未评分记 1.0，不惩罚。收缩靶心与中性锚点是同一个值，否则「中评 + 少票」会比「没评分」更差，「不惩罚」名不符实。
- 个人偏好与场合差评乘子见 §7.4。

### 6.5 连续季节换算与供暖修正 🌱【假设】

底稿的「实时气温 → 有效季节权重」连续加权（如 22–28℃ 记夏 0.6 + 春 0.4）是 §6.2 硬切换的平滑版，保留为储备；「供暖修正」（北方冬季全天室内 → 选香看室内温度、喷量看路上温度）同为储备【经验】。这是上线后最值得用反馈回归验证的模块。

## 7. 用后反馈的校准规则

### 7.1 一问四答 ✅ `FeedbackBar.tsx`

反馈问得极省：只有「今天，刚好吗」一问，四个选项——淡了点 / 刚好 / 太冲了 / 不合场合，点一下即完成。每瓶每天最多记一次（当日去重，刷新也不重复计入）；答完只说一句确认，不追问。反馈即穿过——这瓶当天落进香历。

### 7.2 环境归因 ✅ `FeedbackBar.tsx:envEatsLongevity` + `recommend.ts:aggregateBias`

「淡了点」发生在闷热潮湿 / 干热体感或 ≥28℃ 时 → 记 `env_attributed` 标签，确认语明说：「记下了——不过今天这天气本来就吃留香，这笔算天气的，不扣它的分。」这笔反馈**不进**个人喷量校准——既不让香水背天气的锅，也不让校准被污染。反馈快照里存了体感与湿度（`types.ts:Feedback.context`），归因可回溯。

### 7.3 聚合、衰减与钳位 ✅ `recommend.ts:aggregateBias`

| 反馈 | 偏好 likeScore | 体感强度 perceivedStrength | 其他 |
|---|---|---|---|
| 刚好 | +0.3 | — | 沉淀成功配置（场合 × 温度档 → 当时喷量中值），同键留最新，至多 5 条 |
| 太冲了 | −0.1 | +0.4 | — |
| 淡了点（未归因环境） | −0.05 | −0.4 | — |
| 不合场合 | −0.15 | — | 该场合错配计数 +1 |

所有权重按月衰减 ×0.9（三个月前的反馈约剩七成话语权）——口味会变，偏置不能只增不减、锁死不动；正负双向天然抵消。两项均钳位 [−1, +1]，防连点带飞系统。

### 7.4 校准的兑现路径 ✅

每个信号都有明确的生效位置，不存在「记了但不知道用在哪」的黑箱：

| 信号 | 生效处 | 幅度 |
|---|---|---|
| likeScore | 总分乘子 | 0.75–1.25（`scoring.ts:score`） |
| perceivedStrength | 喷量与有效距离 | ≥0.4 上限 −1（≥0.7 下限再 −1）、有效社交距离降 1 档；≤−0.4 上限 +1（`usage.ts`） |
| sceneMismatch | 该场合总分 | 每次 −10%、封顶 −30%，别的场合不受牵连（`scoring.ts`） |
| successConfigs | 喷量 | 同情境直接复用并显式说明（§3.3） |

### 7.5 轮换与隐式差评 ✅ `recommend.ts`

- **轮换新鲜度** F(d) = 1 − 0.6 × 0.5^(d/2)，d 为距上次采纳隔了几个本地日：d=0 → 1（当天答案不摇摆）、d=1 ≈ 0.58、d=2 = 0.70、d=4 = 0.85、d=7 ≈ 0.95。昨天刚喷的自然让位，久置的自然浮起。**只影响排序，不改内容分与裁决**——「这瓶适不适合今天」和「要不要连着喷它」是两个问题。
- **换瓶隐式差评**：主推被手动换掉，是「分数说它行，你说它不行」。7 天窗口内在 ≥2 个不同天被换掉 → 排名 ×0.8，随时间自动失效，不永久拉黑（`swapPenalty`）。
- **同分轮换**：排名差 <0.012 视作同分簇，簇内按 hash(瓶 id, 本地日) 稳定轮换。先严格降序、再簇内轮换——不把 epsilon 写进排序比较器（epsilon 比较器不满足严格弱序，同质香柜下会出现分高者排后）。日切以本地日为准，避免「今日之选」在早上 8 点整突变。

### 7.6 铁律：校准必须被感知 ✅

每次校准生效都要显式说出来：成功配置复用的说明进「为什么」要点第一条（`recommend.ts:buildPick`），反馈回执直接预告下次的动作（「记下了，下次默认帮你少喷半下。」）。校准的可感知性本身就是留存钩子——「越用越懂你」不能是静默的。

### 7.7 校准储备 🌱【假设】

- **全局扩散敏感度**：多瓶反复嫌冲 → 全局喷量基线下调、密闭场合风险升档；当前偏置全部按瓶隔离，跨瓶的全局校准是下一层。
- **停用询问**：单瓶偏好跌穿阈值时一次性询问「要不要停用这瓶？」——不自动移除。
- **冷启动初值**：onboarding 单选「你希望别人多容易闻到你？」折算初始敏感度。

## 8. 表达规范：如何说人话

完整的术语表、话术红线与真实文案范例见《[声音与文案](声音与文案.md)》，本节只认领与规则相关的四条。

### 8.1 总原则 ✅

1. **一律体感锚点，禁裸数字**：留香说「大半个白天」，距离说「一臂之内」，喷量说「2–3 下」（`format.ts` / `usage.ts`）。
2. **每条建议带「为什么」**：规则生成的要点可追溯到本手册，同时是 DeepSeek 不可用时的兜底解释（`usage.ts:buildReasons`）——解释永远不依赖 LLM 在线。
3. **不确定性外显**：低票记录明说「判断偏保守」，手动记录明说「按所选香调的典型情况估计」（§2.4）。

### 8.2 数字白名单 ✅ `numguard.ts`

反伪精确不靠嘱咐，靠代码：允许出现在 LLM 输出里的数字 = 我们递给它的事实字符串里出现过的数字；事实之外的任何数字（「留香 6.2 小时」「3.7ml」）都是编造——不辩解，整段退回确定性模板。

### 8.3 裁决三档 ✅ `recommend.ts:computeVerdict`

每个候选给一个用香裁决：good 推荐 / caution 留意 / avoid 今天不建议。avoid 的三条触发：天气修正 ≤0.82、反季相对差 ≥0.22、满室档 × 密闭场合。caution：有任何风险条目，或天气修正 <0.95。裁决不迁就用户——确实不合的场景明确判 avoid，但话锋一转给退路：「你要是今天就想用它，就……把存在感压到最低」（✅ `src/app/api/explain/route.ts` 的确定性模板；LLM 回复若不含否定语义，代码强制回退该模板）。

### 8.4 受控风险通道 ✅ `parse-intent`

LLM 对场景的社交常识（「婚礼焦点是新人，不宜喧宾夺主」）只能以 riskNote 这一个受控字段（≤40 字、zod 校验）进入风险提示，去重后追加，不允许自由发挥进正文。规则引擎决策，LLM 表达——边界在代码里，不在约定里。

## 附：置信度总览与验证方式

验证全部走已实现的反馈数据结构（`types.ts:Feedback`）：每条反馈带完整情境快照（季节、时段、温度、场合、体感、湿度）、当时的建议喷量与归因标签，够做分桶回归。

| 模块 | 置信度 | 实现状态 | 上线后验证方式 |
|---|---|---|---|
| §1 环境物理 | 原理【共识】，修正系数【经验】 | ✅ 为主，风 / 干燥 🌱 | 「太冲了 / 淡了点」按 `context.feel` × 温度档分桶，回归 weatherMultiplier 的系数方向 |
| §2 档位映射 | 行业常识【共识】，切点【经验】 | ✅ | 未归因环境的「淡了点」聚在哪个留香档，检验 durationHint 切点 |
| §3 喷量与位置 | 位置禁忌【共识】，喷数档【经验】 | ✅ 主干，完整位置表 🌱 | `Feedback.sprays` 快照 × rating——「刚好」的喷量分布对基础档回归 |
| §4 场合适配 | 方向【经验】，系数【假设】 | ✅ 主干，特殊场景 🌱 | scene_mismatch 按 `context.occasion` × 主香调组聚合 |
| §5 礼仪与中国语境 | 通行部分【共识 / 经验】，本土修正【经验】 | ✅ / 🌱 逐条见 §5.3 | 密闭场合与开阔场合的负反馈率对比 |
| §6 季节时段 | 方法【经验】，反季阈值【假设】 | ✅ 主干，连续换算 🌱 | 反季提示命中时的采纳率与「不合场合」率 |
| §7 反馈校准 | 全部【假设】 | ✅ 主干，全局敏感度 🌱 | 本身即验证机制——校准生效后，同情境「刚好」占比应上升 |
| §8 表达规范 | 产品决策 | ✅ | 数字白名单拦截率（numguard 命中即 bug），文案 A/B |

规则会改，改的依据只有两种：反馈数据，或更硬的领域证据。两种都要落回这本手册——代码与手册不同步，以代码为准，然后修手册。
